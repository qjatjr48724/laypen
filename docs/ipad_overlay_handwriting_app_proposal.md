# iPad 스크린샷 필기 앱 제안서 (Laypen)

- 문서 버전: 0.2
- 상태: 대안 채택 후 MVP 진행
- 대상 플랫폼: iPadOS
- 개발 도구 방향: Cursor를 활용한 단계적 개발
- 관련 문서: [오버레이 검증](overlay_feasibility_verification.md), [MVP 범위](mvp_scope.md)

---

## 1. 프로젝트 개요

### 1.1 목적

iPad에서 Safari, 영상 앱 등 다른 앱 화면을 **시스템 스크린샷으로 가져온 뒤**, Laypen에서 Apple Pencil로 빠르게 메모·표시할 수 있는 간단한 필기 도구를 만든다. 앱은 로그인이나 회원가입 없이 실행 즉시 사용할 수 있어야 하며, 최소한의 조작 UI로 필기 기능을 빠르게 켜고 끌 수 있도록 한다.

**기본 진입 경로(절차 최소화):** `스크린샷 → 썸네일 → 공유 → Laypen` (Share Extension이 필기 화면으로 연결).

### 1.2 핵심 가치

- 다른 앱 화면을 캡처한 뒤 짧은 공유 절차로 즉시 필기
- 화면을 가리지 않는 작고 간결한 도구 UI
- 펜 종류별 색상과 굵기 설정 유지
- 필기 입력을 일시 중지해도 기존 필기는 보존
- 복잡한 계정, 동기화, 문서 관리 기능 없이 빠르게 실행하고 사용

### 1.3 원래 목표와 채택 대안

**원래 목표**는 다른 앱 위에 투명한 인터랙티브 필기 레이어를 올리는 것이었다. 공개 API·플랫폼 조사 결과([검증 문서](overlay_feasibility_verification.md)) 이 요구는 **iPadOS 서드파티 앱으로 충족할 수 없다.**

따라서 1차 제품은 아래 대안으로 범위를 확정한다.

| 구분 | 내용 |
|---|---|
| 채택 | 시스템 스크린샷 + Share Extension(및 앱 내 이미지 선택) 마크업 |
| 비채택(현재) | 다른 앱 위 시스템 전역 투명 오버레이, 백그라운드 자동 스크린샷 수집, 제어 센터에서 타인 화면 캡처 |
| 이후 | OS가 공개 API로 오버레이를 열면 `BackgroundSource`만 교체하고 필기 코어는 재사용 |

원래 오버레이와의 차이: 아래 앱과 **동시에** 조작·필기하는 경험이 아니라, **정지된 화면 이미지 위**에 필기한다.

## 2. 범위와 우선순위

### 2.1 핵심 목표

1. 스크린샷을 공유로 열어 필기하는 사용 경험을 제공한다.
2. 도구 UI와 필기 ON/OFF 버튼으로 기능을 빠르게 제어한다.
3. 검은색 펜, 컬러 펜, 형광펜, 지우개를 제공한다.
4. 각 도구의 설정을 도구별로 기억한다.
5. 필기 ON/OFF를 전환해도 이미 그린 내용은 보존한다.

### 2.2 개발 우선순위

| 우선순위 | 항목 | 상태 |
|---|---|---|
| P0 | 오버레이 구현 가능성 검증 | **완료** — 공개 API로 불가 |
| P0 | 대안 채택(스크린샷 + Share) | **확정** |
| P1 | Share Extension 진입 + 필기 캔버스 | MVP |
| P1 | 최소 도구 UI와 ON/OFF | MVP |
| P1 | 펜, 컬러 펜, 형광펜, 지우개 | MVP |
| P1 | 필기 ON/OFF 및 기존 필기 보존 | MVP |
| P2 | 실행 취소 및 다시 실행 | MVP |
| P2 | 도구별 색상·굵기·크기 설정 유지 | MVP |
| P2 | 현재 작업 로컬 자동 저장·복원 | MVP |
| P3 | 세부 UX 개선 및 시각적 완성도 | 개발 중 조정 |

세부 In/Out은 [mvp_scope.md](mvp_scope.md)를 따른다.

## 3. 사용자 흐름

1. 사용자가 다른 앱에서 **시스템 스크린샷**을 촬영한다. 로그인·회원가입은 없다.
2. 스크린샷 썸네일에서 **공유 → Laypen**을 선택한다. (보조: 메인 앱에서 앨범/최근 스크린샷 선택)
3. Laypen 필기 화면이 열린다. 메인 도구 아이콘을 누르면 도구 메뉴가 열리고, 다시 누르면 닫힌다.
4. 별도의 필기 ON/OFF 버튼으로 필기 입력을 시작하거나 일시 중지한다.
5. 메뉴에서 펜 종류를 선택하고 필요한 색상과 굵기를 조절한다.
6. 필기 중 OFF로 전환하면 새로운 필기 입력만 막고 기존 필기 내용은 유지한다.
7. 지우개를 사용해 일부 필기를 지우거나, 별도 명령으로 화면의 필기를 전체 삭제할 수 있다.

## 4. 도구 UI

### 4.1 메인 도구 아이콘

- 화면 가장자리 가까이에 작은 아이콘으로 표시한다.
- 화면의 다른 위치로 이동할 수 있다.
- 메인 아이콘과 ON/OFF 버튼은 하나의 묶음처럼 함께 이동한다.
- 메인 아이콘을 누르면 도구 메뉴가 열리고, 다시 누르면 닫힌다.
- 상시 노출 UI는 꼭 필요한 정보만 표시한다.

### 4.2 필기 ON/OFF 버튼

메인 아이콘 옆에 별도의 버튼을 둔다. 버튼에는 펜 아이콘과 `ON` 또는 `OFF` 텍스트를 함께 표시한다.

| 상태 | 표시 및 동작 |
|---|---|
| OFF | 회색 계열로 표시하고 새 필기 입력을 받지 않는다. |
| ON + 검은색 펜 | 검은색 계열로 표시한다. |
| ON + 컬러 펜 | 선택된 펜 색상을 반영한다. |
| ON + 형광펜 | 선택된 형광펜 색상을 반영한다. |
| ON + 지우개 | 흰색 배경에 지우개 아이콘을 표시한다. |

- 버튼 색상이 밝거나 어두워도 아이콘과 텍스트를 알아볼 수 있도록 대비를 조절한다.
- `ON`/`OFF` 텍스트는 색상과 관계없이 유지한다.
- ON/OFF 버튼을 눌러도 기존 필기는 삭제되지 않는다.
- OFF 상태에서는 새로운 필기·지우개 입력을 받지 않는다.

### 4.3 현재 도구 표시

- ON/OFF 버튼의 색상과 아이콘으로 현재 선택된 도구를 표현한다.
- 상세한 도구 정보와 설정은 메뉴를 열었을 때 확인할 수 있도록 한다.
- 색상만으로 도구 종류를 구분하기 어려운 경우 아이콘 또는 짧은 라벨을 함께 제공한다.

### 4.4 메뉴 표시

- 메인 아이콘을 눌렀을 때 메뉴를 열고 닫는다.
- 메뉴가 닫혀 있을 때는 상세 설정을 노출하지 않는다.
- 메뉴는 필기 대상 화면을 가능한 한 적게 가리도록 배치한다.
- 화면 가장자리나 기기 방향에 따라 메뉴가 화면 밖으로 잘리지 않도록 한다.

## 5. 필기 도구

### 5.1 검은색 펜

- 검은색으로 필기한다.
- 선 굵기를 조절할 수 있다.
- 검은색 펜의 굵기 설정은 다른 도구로 전환해도 유지한다.

### 5.2 컬러 펜

- 사용자가 색상을 선택할 수 있다.
- 선 굵기를 조절할 수 있다.
- 마지막으로 선택한 색상과 굵기를 기억한다.

### 5.3 형광펜

- 사용자가 형광펜 색상을 선택할 수 있다.
- 선 굵기를 조절할 수 있다.
- 일반 펜과 구분되는 반투명한 표시를 기본 방향으로 한다.
- 마지막으로 선택한 색상과 굵기를 기억한다.

### 5.4 지우개

- Apple Pencil로 드래그한 부분의 필기만 지운다.
- 지우개 크기를 조절할 수 있다.
- 지우개 크기 설정은 다른 도구로 전환해도 유지한다.
- 별도 명령으로 전체 필기를 지우는 기능도 제공한다.
- 전체 삭제는 실수 방지를 위해 확인 단계를 두는 방향으로 한다.
- 지우개는 필기 획 전체를 삭제하는 방식이 아니라, 드래그 경로에 닿은 부분을 지우는 방식으로 설계한다.

### 5.5 실행 취소 및 다시 실행

- `Undo`: 직전 필기 또는 지우기 작업을 취소한다.
- `Redo`: 취소한 작업을 다시 적용한다.
- 연속된 필기와 지우기 작업의 순서가 유지되어야 한다.
- 기록 범위와 메모리 제한은 구현 단계에서 결정한다.

## 6. 도구 설정

### 6.1 도구별 설정 유지

각 도구는 설정을 독립적으로 보관한다.

| 도구 | 유지할 설정 |
|---|---|
| 검은색 펜 | 선 굵기 |
| 컬러 펜 | 선택 색상, 선 굵기 |
| 형광펜 | 선택 색상, 선 굵기 |
| 지우개 | 지우개 크기 |

도구를 바꾸었다가 돌아오더라도 해당 도구의 마지막 설정을 복원한다.

### 6.2 설정 UI

- 상세 설정은 도구 메뉴를 열었을 때만 표시한다.
- 색상 선택 UI는 컬러 펜과 형광펜에 각각 제공한다.
- 굵기 및 크기는 슬라이더 등 직관적인 조작 방식을 우선 검토한다.
- 가능하다면 설정 영역에 실제 굵기를 보여주는 미리보기 선을 표시한다.
- 색상 팔레트의 구성과 세부 수치는 MVP에서 임시 기본값을 쓰고 이후에 조정한다.

## 7. 필기 입력 상태와 데이터 처리

### 7.1 입력 장치

- 필기 입력은 Apple Pencil만 지원한다.
- 손가락 터치는 필기 입력으로 처리하지 않는다.
- 손가락 터치는 메뉴, 버튼, 슬라이더 등 앱 UI를 조작하는 용도로 사용한다.
- Apple Pencil 입력과 손가락 터치가 혼동되지 않도록 실제 iPad에서 검증한다.

### 7.2 ON/OFF 규칙

- ON: 선택한 도구로 필기 또는 지우기 입력을 받을 수 있다.
- OFF: 새로운 필기 및 지우기 입력을 받지 않는다.
- OFF로 바꾸어도 기존 필기 내용은 그대로 유지한다.
- 다시 ON으로 바꾸면 기존 필기가 남아 있는 상태에서 계속 작업할 수 있다.

### 7.3 배경 소스와 필기 데이터

- **배경 소스(`BackgroundSource`):** MVP는 스크린샷/공유 이미지. 이후 오버레이 등이 가능해지면 이 계층만 교체한다.
- 필기 스트로크와 도구 설정을 서로 구분해 관리한다.
- Undo/Redo를 지원할 수 있도록 작업 이력을 관리한다.
- MVP는 현재 작업의 로컬 자동 저장·다음 실행 복원을 포함한다. 다중 문서·앱별 공간은 이후.
- 다른 앱의 화면을 **무단으로 상시 캡처**하는 기능은 포함하지 않는다. 사용자가 만든 시스템 스크린샷·공유 이미지만 사용한다.

## 8. 앱 실행과 종료

### 8.1 실행

- 계정 생성이나 로그인을 요구하지 않는다.
- Share Extension 또는 메인 앱 실행 후 핵심 기능으로 빠르게 진입하도록 한다.

### 8.2 종료 버튼

도구 메뉴에 `앱 종료` 항목을 넣고 싶다는 요구가 있으나, iPadOS에서는 일반 앱이 스스로 앱 프로세스를 강제 종료하는 동작을 제공하는 것이 적절하지 않다.

따라서 이 항목의 실제 의미는 아직 확정하지 않는다. 구현 전 아래 중 어떤 동작이 필요한지 결정해야 한다.

- 도구 UI를 숨기거나 비활성화한다.
- 필기 입력을 OFF로 전환한다.
- 앱 사용을 종료하는 방법을 안내한다.

이 기능을 실제 앱 강제 종료로 구현한다고 가정하지 않는다.

## 9. 플랫폼 및 기술 검증 (요약)

상세 내용은 [overlay_feasibility_verification.md](overlay_feasibility_verification.md)를 본다.

- 다른 앱 위 투명 인터랙티브 오버레이: **공개 API로 불가**
- 채택 대안: **스크린샷 + Share Extension**
- UIWindow / Slide Over / PiP / ReplayKit 등은 원래 오버레이 요구를 충족하지 않거나 부분 대안일 뿐이다.

## 10. Cursor 기반 개발 진행안

### 1단계: 요구사항 및 플랫폼 검증 — 완료
- 오버레이 불가 확인, 대안 비교·사용자 승인, MVP 범위 문서화.

### 2단계: MVP 구현
- Share Extension 진입, PencilKit(또는 동등) 캔버스, 도구 UI, ON/OFF, Undo/Redo, 로컬 저장.

### 3단계: 통합 테스트
- 공유 진입, 도구 전환·설정 유지, Pencil/손가락 분리, ON/OFF, 저장·복원.

### 4단계: 문서 및 안정화
- 실제 구현 결과와 미구현 항목을 문서에 반영한다.
- 오버레이를 완료된 기능으로 표시하지 않는다.

## 12. 미확정 항목 및 확장 아이디어 후보

## 13. 완료 기준

핵심 기능의 완료 여부는 UI가 화면에 표시되는지만으로 판단하지 않는다.

1. 스크린샷 공유로 Laypen 필기 화면이 열리는지 확인한다.
2. ON/OFF 전환 시 기존 필기가 유지되는지 확인한다.
3. 네 가지 도구가 각자 의도한 동작을 수행하는지 확인한다.
4. 도구별 설정이 전환 후에도 유지되는지 확인한다.
5. 부분 지우기, 전체 삭제, Undo/Redo가 올바르게 동작하는지 확인한다.
6. 도구 UI가 화면 가장자리에서 잘리지 않고 함께 이동하는지 확인한다.
7. 미지원 기능(특히 시스템 전역 오버레이)과 플랫폼 제한사항을 문서에 정확히 남긴다.

## 14. 최종 원칙

이 프로젝트는 기능을 많이 넣는 것보다 **짧은 절차로 화면을 가져와 Pencil로 필기하는 핵심 경험**을 실제 iPad에서 제공하는 것이 중요하다.

시스템 전역 오버레이는 현재 불가하므로, 검증된 대안(스크린샷 + Share)으로 MVP를 진행한다. 배경 소스와 필기 코어를 분리해, 나중에 플랫폼이 허용하는 방식이 생기면 교체할 수 있게 둔다. 범위를 바꿀 때는 원래 목표와의 차이를 문서에 남긴다.
